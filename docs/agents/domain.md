# Domain docs

This project uses a single-context layout. Paths below are relative to the
homework project directory, rather than the enclosing Git repository root.

## Before exploring

- Read the project's `CONTEXT.md` for domain vocabulary.
- Read ADRs under `docs/adr/` that concern the area being changed.
- If either is absent, proceed silently. Create domain docs lazily when terminology or architectural decisions are resolved.

## Vocabulary and decisions

Use the terms defined in `CONTEXT.md` for domain concepts in specs, tickets,
code, tests, and explanations. If a needed concept is missing, assess whether
it is a real glossary gap before introducing new terminology.

If a proposal conflicts with an existing ADR, identify the ADR and explain
the conflict explicitly before changing the recorded decision.
