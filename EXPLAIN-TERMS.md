# Словарь терминов к EXPLAIN.md

Здесь собраны термины, которые встречаются в [объяснении проекта](EXPLAIN.md). Некоторые слова знакомы по общему смыслу, но в программе обозначают более конкретные вещи.

## Юридические ссылки и их уровни

| Термин | Значение | Пример из проекта |
|---|---|---|
| <a id="legal-reference"></a>Юридическая ссылка | Фрагмент текста, который указывает на одну или несколько норм закона. | `пп. 1, 2 п. 3 ст. 5 НК РФ` |
| <a id="provision"></a>Норма | Конкретное положение закона, на которое указывает ссылка. Одна ссылка со списком может обозначать несколько норм. | Подпункт 1 пункта 3 статьи 5 НК РФ — одна норма. |
| <a id="hierarchy-level"></a>Уровень нормы | Место обозначения в иерархии закона: статья, часть, пункт, подпункт или абзац. | В примере выше указаны подпункт, пункт и статья. |
| <a id="marker"></a>Маркер | Слово или сокращение, которое называет уровень нормы. Маркер сам по себе не является номером этого уровня. | `ст.` — маркер статьи, `п.` — маркер пункта, `пп.` — маркер подпункта по правилам этого задания. |
| <a id="identifier"></a>Идентификатор | Текстовое обозначение статьи, пункта или другого уровня. Программа сохраняет его как строку: точки, буквы и дефисы могут быть значимыми. | `12`, `4.6`, `а`, `43.2-6`. |
| <a id="selector-list"></a>Список значений | Несколько идентификаторов одного уровня, перечисленных в одной ссылке. Семантический анализатор создаёт отдельный результат для каждого. | `пп. 1, 2` означает два подпункта. |
| <a id="range"></a>Диапазон | Включительная последовательность значений одного уровня. Проект раскрывает только поддерживаемые виды диапазонов. | `5–7` может дать значения 5, 6 и 7; дефис внутри идентификатора сам по себе диапазон не задаёт. |
| <a id="branch"></a>Ветка | Одна из частей ссылки, соединённых перечислением или союзом. Ветки могут относиться к общей статье или закону. | В `часть 1 и часть 2 статьи 5` обе ветки используют статью 5. |

## Термины поиска и разбора

| Термин | Значение | Где встречается |
|---|---|---|
| <a id="lexical-analysis"></a>Лексический анализ | Поиск в тексте слов и обозначений, которые могут быть частями юридической ссылки, и присвоение им возможных типов. | `ReferenceAnalyzer` в `reference_parser.py`. |
| <a id="token"></a>Токен | Распознанный элемент текста с типом и исходной позицией. В проекте это может быть маркер, идентификатор, союз или название закона. | Лексический анализ; например, `ARTICLE`, `ID`, `LAW`. |
| <a id="lexical-candidate"></a>Лексический кандидат | Один из возможных вариантов того, чем может быть фрагмент текста. Несколько вариантов сохраняются, если текст допускает разные прочтения. | Результат распознавания в `reference_parser.py`. |
| <a id="edge"></a>Ребро (edge) | Внутреннее представление возможного токена от одной позиции текста до другой. Ребро может охватывать несколько слов, например название закона. | Связи между позициями при лексическом анализе. |
| <a id="law-alias"></a>Алиас закона | Название или сокращение, которое словарь связывает с ID закона. В тексте алиас может быть в другой падежной форме. | `НК РФ` — алиас Налогового кодекса в `law_aliases.json`. |
| <a id="unknown-law"></a>Неизвестный закон | Название закона распознано, но ему не соответствует ID в словаре. | Внутренний результат сохраняет ссылку, а `law_id` остаётся пустым. |
| <a id="unspecified-law"></a>Неуказанный закон | В ссылке нет названия закона. Это отличается от неизвестного закона, который упомянут, но не сопоставлен со словарём. | `ст. 5` без названия закона. |
| <a id="ambiguous-alias"></a>Неоднозначный алиас | Название закона сопоставлено с несколькими ID. | Внутри сохраняются все кандидаты; при формировании ответа выбирается минимальный ID. |
| <a id="grammar"></a>Грамматика | Набор правил, описывающий допустимое строение юридических ссылок. Это не правила построения всего русского предложения. | `docs/reference-grammar.bnf`. |
| <a id="syntax-parse"></a>Синтаксический разбор | Определение того, как найденные токены связаны друг с другом по грамматике. | Например, какой пункт относится к какой статье. |
| <a id="ast"></a>Дерево разбора (AST) | Представление структуры ссылки в виде узлов и листьев. Узлы показывают связи, листья содержат распознанные элементы и позиции в тексте. | `AstNode` и `AstLeaf` в `reference_parser.py`. |
| <a id="parse-alternative"></a>Альтернатива разбора | Другой допустимый вариант структуры для того же фрагмента текста. | Earley-парсер может сохранить несколько таких вариантов. |
| <a id="candidate-span"></a>Фрагмент-кандидат (`CandidateSpan`) | Найденный диапазон исходного текста вместе с деревьями возможных разборов и признаками полноты. | Результат поиска ссылок в `reference_parser.py`. |
| <a id="overlapping-spans"></a>Перекрывающиеся фрагменты | Два найденных диапазона, где один начинается до окончания другого. Короткий фрагмент может быть началом более длинной ссылки. | Семантическая стадия выбирает наиболее длинную поддержанную интерпретацию. |
| <a id="earley"></a>Earley | Алгоритм синтаксического разбора, используемый Lark. Здесь он нужен, чтобы сохранять неоднозначные варианты грамматического разбора. | Конфигурация парсера в `reference_parser.py`. |
| <a id="parse-shape-cache"></a>Кэш формы разбора | Хранилище структуры разбора, ключом которого служит последовательность типов токенов. Исходные значения и позиции при повторном использовании подставляются заново. | Ограниченный кэш в `ReferenceAnalyzer`. |

## Термины интерпретации и результата

| Термин | Значение | Пример из проекта |
|---|---|---|
| <a id="semantic-analysis"></a>Семантический анализ | Интерпретация дерева разбора: определение значений уровней, объединение общих частей ссылки и раскрытие списков. | Список `пп. 1, 2` превращается в два пути нормы. |
| <a id="provision-path"></a>Путь нормы (`ProvisionPath`) | Внутренняя запись одной нормы со всеми распознанными уровнями и сведениями о законе. Она хранит больше деталей, чем ответ API. | Статья, часть, пункт, подпункт, абзац и статус закона. |
| <a id="diagnostics"></a>Диагностика | Запись о том, что разбор или перенос данных имеет ограничение, неоднозначность либо нерешённый случай. | Неподдерживаемый диапазон или уровень, отсутствующий в схеме API. |
| <a id="context"></a>Контекст | Информация из более ранних ссылок в том же тексте, которую можно использовать для заполнения пропусков. | Предыдущий явно названный закон может быть унаследован следующей ссылкой. |
| <a id="context-resolution"></a>Разрешение контекста | Отдельный проход по результатам слева направо для восстановления пропущенного закона или статьи. | `ContextualResolver` в `contextual_resolver.py`. |
| <a id="self-reference"></a>Самоотсылка | Указание на закон или уровень, который содержит текущий текст, без явного номера или названия. | «настоящей статьи»; без доступного контекста номер может остаться неизвестным. |
| <a id="anaphoric-reference"></a>Анафорическая ссылка | Ссылка словами вроде «указанная статья», смысл которой зависит от ранее названного объекта. | Номер статьи ищется среди совместимых предыдущих ссылок. |
| <a id="result-projection"></a>Проекция результата | Перенос внутреннего пути нормы в более узкий формат ответа API. Если есть и часть, и пункт, поле `point_article` получает пункт; часть отдельно не возвращается. Абзац тоже не входит в ответ. | `law_link_mapper.py` формирует поля `law_id`, `article`, `point_article`, `subpoint_article`. |
